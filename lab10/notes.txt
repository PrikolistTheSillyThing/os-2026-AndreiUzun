3.3 Only write (bit 16, mask 65536)
-----------------------------------
$ trace 65536 echo hi
hi13: syscall write -> 2

13: syscall write -> 1


Observe
-------

1. In "trace 32 grep hello README" why do you see only read, and not
   open or close?

   Mask 32 = 2^5, so only bit 5 is on, and 5 is SYS_read. The kernel
   prints a call only if (mask >> num) & 1 is true. For open (15) and
   close (21) that bit is 0, so grep still calls them, but they are
   not traced.

2. In forkforkfork, three different pids print lines. Which line of code
   from Part 2 makes that possible?

   np->trace_mask = p->trace_mask; in fork() in kernel/proc.c (step 2.5).
   trace sets the mask on itself and then exec keeps it for usertests.
   Every fork copies the parent's mask into the child, so the children
   (and their children) are traced too. Without this line only the first
   process would print, because the children would start with mask 0.

3. In "trace 65536 echo hi" the trace line is printed between "hi" and
   the new line. Why? (How many times does echo call write?)

   echo calls write twice: once for "hi" (2 bytes, returns 2) and once
   for the newline (1 byte, returns 1). The kernel prints the trace line
   right after each call returns, so the first trace line appears
   directly after "hi" and before the "\n" is written. That is also
   where the blank line comes from.

4. Which mask traces both open (15) and close (21), and nothing else?

   2^15 + 2^21 = 32768 + 2097152 = 2129920.

   Check:
   $ trace 2129920 grep hello README
   77: syscall open -> 3
   77: syscall close -> 0
